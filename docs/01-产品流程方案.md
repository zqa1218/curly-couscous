# 摄影企划工作台 产品流程方案

## 一、产品定位

一个本地优先的摄影企划工作台，把"一句风格关键词 + 人物和道具"变成一个可以直接开拍的完整方案，最后输出图文并茂的 PDF。

产品的核心不是让 AI 替人做决定，而是让人在每一个分叉口做选择。AI 负责提议、检索、拆解和整理，人负责点采纳、点否决、写新想法。所有 AI 产出都以候选形式出现，只有被人采纳后才进入正式数据。

使用者是独立摄影师、小型拍摄团队和 Cos 企划者，工作场景是坐在电脑前长时间面对图片和画布。

## 二、核心设计原则

1. **人在环，AI 只提议**。每个 AI 输出都是一张候选卡片，带采纳、忽略、改写三个动作，不采纳就永远不进项目数据。
2. **一切可追溯**。每条灵感都能回答"它来自哪张图的哪个维度"，PDF 里同样标注来源编号。
3. **画布是唯一自由区**。流程的其他环节都按固定步骤推进，只有黑板允许随便摆、随便连、随便写。
4. **本地优先**。项目、图片、API key 都在本机，不依赖任何云服务；换台机器拷走项目文件夹就能继续。
5. **AI 失败不阻塞流程**。任何一步 AI 不可用，人都能手动填写或跳过，流程继续。

## 三、技术架构

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vite + React + TypeScript | 单页应用，本地开发体验好 |
| 样式 | 原生 CSS 变量 + CSS Modules | 不引入 UI 组件库，避免所有页面长得一样 |
| 画布 | Excalidraw（MIT） | 无限画布、图片元素、可绑定连线、手写便签，文件是 JSON 可脚本生成 |
| 本地服务 | Node + Fastify | 文件读写、图片下载、AI 代理、PDF 导出 |
| 数据 | 项目文件夹 + JSON | 单文件即单一真相源，可读、可 diff、可手动修 |
| AI | OpenAI 兼容接口 | 用户自填 base_url、api_key、模型名，可接国内模型 |
| PDF | 渲染层抽象，默认复用 Word 链路 | 已在本机验证可用，中文字体零风险；后续可换 HTML 方案 |

不选 Tauri 是因为本机没有 Rust 工具链；不选纯云端是因为图片和 API key 都需要留在本地。

## 四、数据模型

每个项目一个文件夹，结构固定：

```
projects/项目名-20260928/
  project.json          全部结构化状态，前端只读这一份
  assets/
    refs/               例图原图
    uploads/            用户上传（布光图、模特照、道具照）
    generated/          AI 生成图
    thumbs/             缩略图
  board/
    board.excalidraw    黑板场景
  docs/                 各阶段导出的 Markdown
  output/               PDF 和 docx
```

## 五、详细流程

八个阶段，每个阶段都标注谁做什么。AI 一栏里所有产出都是候选，人一栏里所有动作都是决定。

### S0 立项输入

人按四组填写：拍摄对象（人物或角色、道具）、拍摄场景、风格与镜头（风格关键词、焦段、光圈）、执行与效果（拍摄手法、拍摄前期效果、拍摄后期效果）。

场景与手法分开，是因为这两件事在现实里由不同条件决定：场景决定去哪、光线如何，手法决定怎么拍、机位怎么摆。分开之后 S1 的选址建议只依据场景一栏，不会被手法描述带偏。

焦段与光圈单独成项，是因为它决定整组图的镜头语言：透视压缩、景深厚薄、背景虚化程度都由此而来。这两项会一路带到 S2 的风格深化、S4 的例图拆解和 S5 的灵感归档，作为判断"这张图为什么长这样"的依据。

前期效果与后期效果也分开：前者是实拍阶段就要做出来的东西（烟雾、水汽、逆光眩光），后者是后期加工（调色、颗粒、合成）。分开写，S6 的布光建议才不会把后期能解决的事推到现场。

**AI 在 S0 就介入。** 每个关键字段旁边都有 AI 按钮：道具可以推荐、风格关键词可以推荐、拍摄场景可以推荐、拍摄手法和前后期效果既可以推荐也可以把用户已经写的文字细化改写。所有推荐都以候选形式出现，人勾选之后才写进表单，AI 不会直接改动人的输入。

AI 做两件事：把模糊输入补成结构化的项目卡，把缺失的关键信息整理成一份追问清单（例如"没给拍摄城市，这会影响选址和时间建议"）。

产出项目卡。决策点是确认输入没有理解偏差。

### S1 选址与时间

这一阶段把"什么时候拍"和"在哪里拍"分成两件事，前者交给程序算，后者交给 AI 提。

**时间由程序算。** 填城市和日期，程序按经纬度算出日出、正午、日落、昼长，以及早晨与傍晚的黄金时刻、蓝调时刻。用的是天文年历算法，纯本地、不调任何接口，也不让模型去猜时间。算完之后给出六个可直接点的时段（清晨蓝调、早晨黄金、上午、午后、傍晚黄金、傍晚蓝调），点一下就带着具体时间写进方案。

**场地由 AI 提。** AI 根据人物、道具、场景与风格给出五个场地候选，每个都必须写清四件事：光线条件（朝向、进光方式、遮挡）、一天中最适合的时段、需要提前确认的限制（收费、报备、人流）、以及它为什么匹配当前风格。它给的是可迁移的场地类型，不是编造的门牌号；具体去哪一家由人定。

产出一份"城市 + 日期 + 场地 + 时段"的决定。决策点是人选择用哪个场地、在哪个时段拍。

城市表内置 47 个城市（国内主要城市加日韩东南亚与欧美主要城市），支持"上海市"这类写法，按城市标准时区换算，不处理夏令时。

### S2 人物形象调研与主题定调

AI 搜集人物或角色的资料：出典作品、原始设定、服装与配色规律、标志性元素、常见的画错或拍错的地方。然后给出两到三个主题定调方向，每个方向包含一句话主张、视觉走向、以及深化拍摄风格的具体建议。

人选定一个方向，或者把几个方向的要素重新组合。

产出角色档案和主题定调卡。决策点是主题方向定稿。

这一阶段立了一条硬规矩：**不确定的信息必须标"需要核实"，不许编造设定。** 面对真实角色（例如初音未来），它会给出准确的出处、设计师、官方身高体重、配色规律与易错点；面对虚构或不知名的拍摄对象，它会明确写出"需要核实身份设定""需要核实身高体型"，并说明该查什么，而不是编一套听起来合理的话。对摄影企划来说，一个假的设定比一句"不知道"危险得多。

档案的六条固定覆盖：出典与身份、外形与体型特征、服装与配色规律、标志性元素（必须出现与必须避免）、容易被拍错的地方、可选的表现气质。

主题定调要求三个方向之间有明显区别（偏叙事、偏氛围、偏造型），每条都要能回答"一句话主张是什么、视觉往哪走、具体怎么拍"。AI 还会主动指出冲突，例如角色官方气质与本次风格取向不一致时，提醒需要跟客户确认是否允许风格化改编。

### S3 参考例图检索

改成了口袋式收集。程序化抓取行不通——Pixiv、ArtStation、Wikimedia 这些站点一律拒绝程序访问，所以这里不做抓取，只做两件事：告诉你去哪找、帮你把找到的图分门别类存好。

第一步是**找图目录**。产品内置一份人工筛选过的站点清单，按三类用途分组，每个站点都写清它适合找什么、标签要用中文还是英文、能不能直接导进来。填一个搜索词，所有站点的直达链接会同时带上这个词，点开就是搜索结果页。清单里的链接都做过连通性实测。

1. **优秀原画**：Pixiv、Danbooru、Gelbooru、yande.re、Safebooru、ArtStation，当后期素材与动作参考。
2. **优秀 Cos 作品**：WorldCosplay、Lofter、哔哩哔哩、微博，当动作、风格与后期参考。
3. **抽象风格画作**：花瓣、站酷，当背景氛围与主题思想参考。

第二步是**口袋**。三个分类各是一个口袋，人在浏览器里挑好图之后，拖进来或粘贴直链导入，程序负责落盘、生成缩略图、按内容哈希去重、登记来源链接与作者。每张图记录来源链接、作者、站点和它被归入哪一类。

产出参考图库与来源索引。决策点是哪些图值得拿到公共区去用。

**为什么不做自动抓取**：实测下来，Danbooru 与 ArtStation 对程序访问返回 403，Wikimedia 返回 400，Pixiv 需要登录才看全。与其做一个经常失败还要维护反爬的抓取器，不如把网页交给人，把整理工作交给程序。

### S4 黑板（人主导）

这是整个产品的主场景，从上到下一共四层。

**第一层，口袋翻页条。** 顶端横向摆出口袋里的图，一页四张，左右翻页。点一张就把它送到下面的布置台。这样不用离开黑板就能反复取用不同的图。

**第二层，布置台。** 三步走：

1. AI 提取元素。让模型看图，列出这张图里可以抽离出来单独使用的元素，例如逆光发丝、斑驳树影、冷调背景、黄铜反光。每条都写清它在图里怎么表现、由什么构成、抽离出来能用在哪个环节。
2. 人挑元素。勾选真正想用的，抽离成标签挂在这张图上；不想用的直接不勾。
3. 决定以什么身份放进公共区。这里分两条路，性质完全不同：

   **作为完整想法放入** —— 先写灵感或让 AI 补全成完整场景策划（画面描述、光线方案、镜头与构图、道具与造型、执行注意点），再放进去。完整想法是终态，进去之后不再参与连线，因为它本身已经是一个能开拍的完整方案。

   **作为组成元素放入** —— 只带抽离出来的元素进去，不写灵感也不补全。组成元素不是完整想法，它必须和别的组成元素连起来，连成一组之后，再由 AI 或人来补全。

口袋里的原图不会被消耗，可以反复取用同一张，每次抽不同的元素、写不同的方向。

**第三层，公共区。** 图可以任意拖动，位置自动保存。每张图带着自己被抽离的元素和灵感，卡片上直接标出元素数量。

**第四层，连线与分组补全。** 组成元素之间可以拉线。连线不是终点，它只是把元素串起来的方式：

- 一组不限于两张：A 连 B、B 连 C，系统会把它们认成同一组，面板上直接显示"这一组（3 个组成元素）"，并且会逐条列出每一方带来的是哪些元素。
- 组内可以随时再连第四个、第五个，成员变化后面板会跟着更新。
- 补全有两条路：让 AI 把这一组整合成一个完整想法（每个组成元素都要在最终画面里有明确去处，一个都不能漏），或者自己手写。补全结果记在"这一组"上，同时保留它由哪些元素构成。

完整想法和组成元素在画布上外观不同（实线边框对虚线边框，卡片上有身份标签），一眼能分清哪个还能连、哪个已经是终点。

原有的整图维度分析（布光、色调等九个维度）保留在选中图的面板里，和元素抽取互补：维度分析回答"这张图整体怎么拍的"，元素抽取回答"这张图里哪些零件可以拿来用"。

每一条灵感都与图一一对应：单图灵感挂在图上，连线灵感挂在两个图之间，最后都会被 S5 收录并标注来源。

公共区画布本身支持横向滚动，图摆得再开也够得着。产出是整个公共区的布局、每张图抽离的元素与灵感、图与图之间的连线灵感。决策点是人决定留下哪些元素、哪些灵感。

### S5 灵感归档

程序扫描公共区，把成品收拢成一份清单。来源只有两种，正好对应 S4 的两类对象：

- **完整想法**：公共区里已经补全过的那张图，一条灵感对应一张来源图。
- **组成元素组**：若干组成元素连成一组后补全的结果，一条灵感对应那一组里的全部来源图。

每条灵感都带四样东西：**来源图缩略图**（直接摆出来，做到与图一一对应）、**用到的元素**、**灵感正文**、**完整策划**，再加上人给它标的作用环节（造型、光线、镜头、构图、道具、后期）。

同步是增量的：已经存在的条目会保留人做过的修改，不会因为重新同步就被覆盖回原样。条目可以改文字、标作用环节、移出定稿或直接删除。

产出是一份定稿的灵感清单。决策点是哪些灵感进最终方案。

### S6 布光

布光不是整组一张，而是**每条定稿灵感对应一份**。因为不同灵感的画面、场地、光比要求都不一样，一份通用布光反而没法执行。

每条灵感下面给出两种方式，可以任选一种，也可以都用：

1. **上传灯位图** —— 人自己画好的俯视图、现场照片或手绘扫描件都可以，程序负责落盘并挂到这条灵感上。
2. **AI 推荐灯位** —— 人可以写清要求（只有一盏灯、要保留窗光层次、预算有限），AI 按灯位逐条给出：灯具类型、功率、附件、位置与高度、以及它在这张画面里起什么作用，还包括自然光与反光板。采纳之后形成灯位表，进入最终方案。

每条还留了现场备注，用来记"现场只有两个插座""天花板不能固定"这类实际限制。

产出是每条灵感对应的布光图或灯位表。决策点是灯位确认。

### S7 汇总 PDF

把所有环节合成一份文档，顺序是：

1. 项目概览：人物、道具、场景、风格关键词、焦段与光圈、拍摄手法、前后期效果
2. 时间与地点：城市日期、日出日落昼长、黄金时刻与蓝调时刻、选定的场地与时段
3. 人物与主题：人物档案与主题定调
4. 灵感与来源：每条定稿灵感带它的来源图（直接排版在正文里）、抽离出的元素、灵感正文与完整策划
5. 布光：每条灵感的灯位表或上传的灯位图

产出 docx 与 PDF 两份，都在企划目录的 output 下，可以反复导出覆盖。每条灵感都带着来源图，例图都标注来源站点与作者。

导出走的是本机 Word 链路：先用 python-docx 按统一版式排版，再由 Word 转 PDF，中文字体与分页都有保障；没有 Word 的环境仍会产出 docx。

## 六、界面设计方向

视觉母题取早期摄影的蓝晒印相工艺：冷灰纸面、普鲁士蓝的图像色、铅笔和红笔的批注感。这个母题来自产品本身的题材，而不是通用的仪表盘审美。

色彩：纸面 `#F1F3F5`，深墨 `#111820`，蓝晒主色 `#1D4E89`，浅蓝 `#C7D7E8`，批注红 `#B23A2E`（只用于标记线和待确认状态）。

字体：界面与正文用思源黑体，区块标题用思源宋体增加印刷物气质，编号与参数用等宽。

布局是三栏工作台：

```
+----------+---------------------------+-------------+
| 阶段导航  |        主工作区           | AI 提议面板  |
| S0 - S7  | 表单 / 画布 / 表格切换    | 候选卡片列表 |
| 竖排      |  画布阶段整屏让给黑板     | 采纳 忽略 改写|
+----------+---------------------------+-------------+
```

内容是左对齐，卡片不用统一的圆角和阴影，改用细分隔线和编号系统来区分层级，因为流程本身是有顺序的。

## 七、非功能要求

API key 只存在本地配置文件和服务端环境变量里，不进入前端包，也不提交到 git。

图片分析按维度调用，只分析勾选的维度，避免为一张图付全部维度的钱。

所有长任务（下载图片、批量分析、导出 PDF）都要有进度和取消。

空状态、错误状态、AI 不可用的降级路径在开发阶段就要设计，不留到最后补。

## 八、已知风险

| 风险 | 应对 |
|---|---|
| 参考站点反爬与登录墙 | v1 半自动，链接直达加人工导入 |
| 例图版权 | 仅作内部创作参考，PDF 强制标注来源，商用需另取得授权 |
| AI 对图片的分析偏空泛 | 强制按选中维度输出，并要求给出可执行的拍摄动作，不接受抽象形容词 |
| PDF 分页错乱 | 渲染层抽象成接口，导出前逐页渲染检查 |
| 长时间使用画布性能 | 图片按缩略图加载，原图按需读取 |
