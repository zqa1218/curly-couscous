### S1 选址与时间 已完成

- 天文计算：`apps/server/src/solar.ts`，天文年历算法，纯本地无依赖。输出日出、正午、日落、昼长、早晚黄金时刻、早晚蓝调时刻。
- 内置 47 个城市的经纬度与时区，支持"上海市"这类写法，取城市名前后缀模糊匹配。

### S4 二类模型 重构（完整想法 / 组成元素）

按"两种进入公共区的方式"重新拆了数据模型：

- `BoardItem` 增加 `kind` 字段：`idea`（完整想法，终态，不参与连线）与 `component`（组成元素，必须连线后补全）。
- 布置台第三步给出两个入口：「作为完整想法放入」需要先写灵感或让 AI 补全；「作为组成元素放入」只要求至少抽了一个元素。
- 连线只允许发生在组成元素之间；尝试把完整想法连线会得到明确提示。
- 新增 `BoardGroup`：一组可以由两个以上的组成元素构成，成员通过连线图自动聚合（BFS 找连通分量），成员集合变化时按集合指纹匹配已有组。
- 组补全新增 AI 任务 `group-plan`：要求整合所有成员的元素，并保证每个元素在最终画面里都有明确去处。
- 画布上两类东西视觉可分：完整想法实线边框加蓝色标签，组成元素虚线边框加红色标签。
- S3 的按钮从「取用到公共区」改为「去黑板处理」，点了会带着这张图跳到 S4 并直接进布置台，避免与布置台的入口语义重复。
- 旧数据自动归一化：已经补全过内容的记为完整想法，其余记为组成元素，不影响已存在的企划。

实测：把一个带两个元素的组成元素和另一个连起来后，面板正确识别出"这一组（4 个组成元素）"（此前两条连线已把另外两个串进同一组），AI 补全后 `project.json` 里 `groups` 记录了 4 个成员、用到的元素摘要与完整想法。

## 二、各里程碑任务与验收标准

### M0 脚手架与设计系统

任务：初始化 pnpm 单仓，前端 Vite + React + TypeScript，服务端 Fastify；建立设计令牌（色板、字阶、间距、层级）；搭出三栏骨架与阶段导航；配置开发脚本一条命令同时起前后端。

验收：浏览器打开能看到三栏骨架，点阶段导航能切换中间区；令牌改一处全局生效；前后端各有一个健康检查接口连通。

### M1 项目与数据层

任务：定义 `project.json` 的 TypeScript 类型与校验；实现项目的创建、打开、列表；按约定建目录；实现图片导入（文件、拖拽、粘贴 URL 三种入口）、原图落盘、缩略图生成、去重；实现来源信息登记。

验收：新建项目后目录结构正确；导入一张图后原图、缩略图、来源记录三者齐全；重复导入同一张图会被识别；关掉应用重开项目状态不丢。

### M2 AI 接入层

任务：设置页（base_url、api_key、模型名，区分文本模型和视觉模型）；服务端代理转发请求，key 不进入前端；流式输出；超时、限流、余额不足、模型不存在四类错误的可读提示；无 key 时的降级模式（所有 AI 步骤可手动填写跳过）。

验收：填一个可用的 key 后能跑通一次文本生成和一次图片分析；故意填错 key 时报错信息能看懂；不填 key 时流程仍能手动走完 S0 到 S7。

### M3 S0 至 S2

任务：立项表单（人物、道具、风格关键词、拍摄手法、后期想法）；AI 补全与追问清单；选址候选生成，含本地计算的日出日落与黄金时刻；场地候选卡片的选择交互；人物资料调研输出；主题定调方向生成与选择。

验收：只输入"人物 + 几个关键词"就能得到完整的项目卡；选址候选里能看到具体时段和光线条件；主题定调给出至少两个方向且每个方向带可执行的风格建议；所有候选都能采纳、忽略、改写。

### M4 S3 参考图检索

任务：按三类（抽象风格、优秀原画、优秀 Cos）生成检索方案；每类给出搜索词组合、推荐站点、可点击直达链接；导入区支持拖拽、粘贴 URL、粘贴本地路径；下载失败时给出可复制的原始链接让人手动保存；图库网格与筛选；索引表导出。

验收：生成的链接点开能直接命中对应站点的搜索结果页；一张图从粘贴 URL 到进入图库不超过三步；下载失败的图有明确的文字说明和手动补录入口。

### M5 S4 黑板

任务：集成 Excalidraw；把图库图片以元素形式放入画布；选中图片后右侧面板显示维度勾选；调用视觉模型只分析勾选维度；分析结果生成注释卡贴在图片旁，并用绑定箭头连接；注释卡之间可连线；手写灵感；AI 灵感推荐（输入为目标风格、人物设定、已选中的多个风格片段）；画布自动保存。

验收：选中一张图勾选三个维度，能在图旁生成三张注释卡并且箭头跟着图片走；在两个注释卡之间拉一条线，移动图片后三者的相对关系不乱；AI 推荐的新灵感采纳后留在画布上；关掉重开画布内容完整。

这是最核心的里程碑，也是唯一一个允许拆成两次交付的。

### M6 S5 与 S6

任务：扫描画布生成灵感清单并标注来源图与来源维度；清单的删改与定稿；AI 布光建议生成；建议结构化成灯位表；按灯位数据绘制俯视布光图，灯位可拖动；上传自有布光图并挂到对应灵感。

验收：灵感清单里每条都能点回它来源的那张图；灯位表改一个角度，布光图上的灯位跟着变；上传的布光图能替换自动生成的图并保留标注。

### M7 S7 PDF 导出

任务：定义导出数据契约；实现 PDF 渲染层（默认复用已验证的 Word 链路，接口留出替换空间）；图文模板，含人物地点时间、主题风格、前中后期目标、例图、灵感与来源标注、布光图；导出前逐页渲染检查；同时输出 docx。

验收：导出的 PDF 至少包含四张例图、每条灵感都带来源编号、布光图带灯位标注；无文字截断和表格错位；在 Word 里打开 docx 能继续编辑。

## 四之二、DeepSeek 接入细节

已核对官方文档，实际能力如下。

| 项 | 值 |
|---|---|
| 模型名 | `deepseek-flash`（即 DeepSeek-V4.1-Flash） |
| 接口地址（OpenAI 格式） | `https://api.deepseek.com` |
| 视觉能力 | **支持**，`input_modalities` 包含 image |
| 上下文与输出 | 1M 上下文，最大输出 384K |
| 其他能力 | JSON 输出、工具调用、Responses API、Anthropic 格式均支持 |
| 计费（每 1M token） | 输入缓存未命中 低峰 0.15 美元 / 高峰 0.3 美元；输出 低峰 0.6 / 高峰 1.2 |

三个必须遵守的约束：

1. **图片分析只能用 `deepseek-flash`**。`deepseek-v4-pro` 不支持视觉，视觉相关调用不要指向它。
2. 模型默认开启思考模式。S4 的逐维度图片分析对速度敏感，M2 实现时用非思考模式调用，把思考模式留给 S2 主题定调这类需要推理的环节。
3. 旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 已被官方退役，请求会被转发并计费，配置里不要再使用。

图片分析成本极低：一张参考图约一两千输入 token，按低峰价折算单张不到千分之一美元，可以放心对多张图逐维度分析。
